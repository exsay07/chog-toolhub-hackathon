# Security audit — Chog Toolhub v0.1.0

**Date:** 2026-10-19 · **Type:** internal code-level review + automated scanning by the implementing engineer.
**This is not** an independent penetration test or a smart-contract audit. The app deploys no contracts, but it
signs transactions against third-party routers; an external review is required before handling meaningful funds.

## Scope

`packages/shared`, `apps/server` (auth, sessions, NFT gate, routes, WS hub, workers, providers), `apps/web`
(vault, trade engine, automation runners, agent client, rendering of third-party data), `apps/agent`
(loopback control plane, task isolation), build/CI config, dependencies. Threat model: `SECURITY.md`.

## Findings fixed during the audit (with regression tests)

| ID   | Severity | Finding                                                                                                                                                  | Fix                                                                                  | Test                                            |
| ---- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------- |
| F-01 | Medium   | `/internal/metrics` trusted `remoteAddress === 127.0.0.1`; behind a same-host reverse proxy every public request is loopback → operational data exposed. | Also require no `X-Forwarded-For`/`Forwarded`/`X-Real-IP`; optional `METRICS_TOKEN`. | `hardening.test.ts` F-01                        |
| F-02 | Medium   | Unlimited WebSockets per user (memory/CPU DoS by one account).                                                                                           | `WS_MAX_PER_USER` (default 8), close code 4029.                                      | `hardening.test.ts` F-02                        |
| F-03 | Medium   | Unlimited unreconciled journal entries → a user could flood junk hashes and starve the shared reconciler.                                                | `JOURNAL_MAX_INFLIGHT_PER_USER` (default 50) → 429.                                  | `hardening.test.ts` F-03                        |
| F-04 | Medium   | Tracker polled every tracked address with no ceiling → shared RPC budget exhaustion.                                                                     | `TRACKER_MAX_ADDRESSES_PER_NETWORK` (default 500), counted in metrics.               | review (cap path is a guard clause)             |
| F-05 | Medium   | base58 decoder mishandled leading-zero input (all-`1` strings decoded to one byte too many) → malformed Solana addresses could pass length checks.       | Rewrote encode/decode with the standard algorithm.                                   | `shared.test.ts` round-trip incl. leading zeros |
| F-06 | Low      | Global rate limit applied to health/metrics, masking real behaviour in load tests and probes.                                                            | Exempted `/healthz`, `/readyz`, `/internal/metrics`.                                 | load test                                       |

Functional defects found by E2E and fixed (not security): sign-in never completed after a successful `/verify`
(cache cleared under an active observer); form labels wrapped their controls so accessible names included option
text; bundled server could not find migrations.

## Follow-up review — 2026-10-21 (trade panel, limit/TP/SL, sniper anti-rug, NFT detect, multi-wallet, deploy)

Scope: everything added on 2026-10-21 — `OrderPanel`/presets/limit orders (`lib/trade/orders.ts`,
`lib/automation/limitOrders.ts`), sniper anti-rug + exits, NFT mint detection (`lib/nft/detect.ts`,
`GET /api/nft/collection`), multi-wallet vault (`lib/vault/*`, `PUT /api/trading-wallets/extra`, journal `wallet`),
smooth scrolling, `@solana/web3.js` v3, deploy scripts (`deploy/*.sh`). Checks: code review, lint/typecheck,
unit + e2e (dev and production build), `npm audit --omit=dev` (**0 vulnerabilities**), ShellCheck on the scripts,
live backup → restore cycle on PostgreSQL 17.

| F-09 | Medium   | Orders read back from the account store were only loosely validated; a malformed entry could be executed half-valid.                                              | Per-order validation (side, trigger, price, amount ≤ 100 % for sells, slippage ≤ 50 %, wallet format); bad entries dropped. | `orders.test.ts` malformed orders                    |

| F-11 | Low      | Mint journal idempotency key reused after re-arming / reload → second mint missing from Portfolio.                                                                | Key includes a timestamp.                                                                                                   | review                                               |
| F-12 | Medium   | Documented restore piped a dump into the live database → fails on "already exists" (backups effectively not restorable as documented).                            | `deploy/restore.sh`: safety dump, recreate DB, single-transaction load, automatic rollback.                                 | live PostgreSQL 17 cycle: data identical, app starts |

Reviewed without findings: extra wallets are only usable when their key is in the unlocked vault (`evmSignerFor`
rejects foreign addresses from server configs); funding/sweeping only moves between the vault's own wallets and asks
for confirmation; adding/removing wallets requires the password (vault re-encrypted, extra addresses checked against
the decrypted keys on unlock); the server stores only public addresses and the journal accepts only the user's own
wallets (`wallets.test.ts`); new endpoints require a session; mint detection renders on-chain strings as text;
no `innerHTML`/`eval`; secrets in `deploy/.env*` are git-ignored, created with mode 600, the tunnel token is read hidden.

## Outstanding risks (not fixed — documented)

| ID   | Severity            | Risk                                                                                                                                                                                                                                                                            | Recommendation                                                                                                                                                                |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O-01 | Medium              | Kyber calldata is not fully decoded; recipient check is "our address appears in calldata". Router allow-list, no-fee check, value check and simulation mitigate, but a compromised aggregator API could craft calldata that routes output elsewhere while passing these checks. | Decode `MetaAggregationRouterV2.swap` params (dstReceiver, minReturn) or simulate asset changes (`eth_simulateV1` / state overrides) and require our balance delta ≥ min-out. |
| O-02 | Medium              | Browser vault: XSS on our origin or a malicious extension can use keys while unlocked; no recovery without the user's backup.                                                                                                                                                   | Keep balances small; dedicated browser profile; migrate to MPC/embedded wallet with policies or keep the key in the desktop agent (OS keychain).                              |
| O-03 | Resolved 2026-10-21 | `@solana/web3.js` 1.x → `jayson`/`stream-json`/`uuid` advisories.                                                                                                                                                                                                               | Upgraded to `@solana/web3.js` 3.x (built on `@solana/kit`); `npm audit --omit=dev` is clean.                                                                                  |
| O-04 | Medium              | Server-side inputs drive automated trades **within the user's limits**: tracker events (copy trading), sniper / mint configs (incl. which vault wallets act), and account-synced limit orders. A compromised server or stolen session could trigger such trades.                | Small limits and token allow-lists; emergency stop; future: sign automation configs with a vault-derived key so only the vault owner can create them.                         |
| O-05 | Medium              | Agent pairing token in `sessionStorage` — XSS could start/stop configured farming tasks (within schema/limits).                                                                                                                                                                 | Short TTL already; add per-command confirmation for `startTask` in the agent UI when the desktop companion ships.                                                             |
| O-06 | Low                 | Trading-wallet registration (`PUT /api/trading-wallets`) does not prove key ownership; only affects the user's own analytics.                                                                                                                                                   | Require signatures from both trading keys over a server nonce.                                                                                                                |
| O-07 | Low                 | Provider token images load directly from third-party hosts (reveals viewer IP).                                                                                                                                                                                                 | Proxy/cache images server-side with content-type and size checks.                                                                                                             |
| O-08 | Low                 | Session cache: in multi-instance deployments a revoked session may be honoured for ≤ `SESSION_CACHE_MS` (5 s) on other instances.                                                                                                                                               | Redis-backed revocation pub/sub, or set `SESSION_CACHE_MS=0`.                                                                                                                 |
| O-09 | Low                 | CSP `style-src 'unsafe-inline'` (required by React inline styles / charting).                                                                                                                                                                                                   | Move to nonce-based styles if feasible.                                                                                                                                       |
| O-10 | Low                 | Agent releases are not code-signed and have no update channel yet.                                                                                                                                                                                                              | Signed installers (Authenticode / notarisation) + checksum-verified updates.                                                                                                  |
| O-11 | Info                | Public RPCs and GeckoTerminal's 30 req/min cap limit availability; 429s were observed during testing.                                                                                                                                                                           | Paid RPCs + CoinGecko Pro key in production.                                                                                                                                  |
| O-12 | Info                | Real-funds execution paths (EVM swap, Solana swap, approval, mint) are not yet exercised end-to-end.                                                                                                                                                                            | Canary wallet runs per network before enabling for users (IMPLEMENTATION_PLAN M8).                                                                                            |
